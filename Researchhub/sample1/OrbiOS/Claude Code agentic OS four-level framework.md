## What it is

A 31-minute, direct-to-camera YouTube explainer by the creator behind the "Chase AI" channel (also runs a paid community/course, "Chase AI Plus," plugged mid-video). Not a tool, repo, or product release — it is **a named framework the creator is teaching**: "Agentic OS" (he also writes it "AIOS") as a mental model for organizing everything you already do with a coding agent CLI into a coherent, personally (or team-)owned system. On-screen visuals are hand-drawn diagrams via a diagramming tool for the mental model, plus live terminal and custom-dashboard screen recordings as proof.

The four levels, per the video's own framing (timestamps from the transcript):

1. **[00:48-13:29] Level 1 — Skill + loop engineering (the backbone).** A "workflow audit" first: figure out what you actually do repeatedly with the coding agent CLI before creating skills for it. Three audit methods demonstrated: (a) manual — you already know the task, use a skill-creation helper; (b) mine your last N sessions' tool-call history for repeated tasks and have the agent propose skills from real usage data (shown live on screen: a "Repeated Tasks → Proposed Skills" table); (c) a stream-of-consciousness interview where the agent asks you about your day/week and extracts skill candidates. Once codified as a skill, promote it to an automation (the desktop app's "routines": name + instructions + schedule), and optionally layer a self-improvement loop on top (pointed to his separate prior "loop engineering" video, not covered in depth here).
2. **[13:29-23:24] Level 2 — Memory + state.** Explicitly states a dedicated vault app is not required — "even more so than the vault app, it's the idea of file structures." A vault is just a folder; opening the coding agent CLI inside it connects the two. The Karpathy-credited `raw/ → wiki/ → outputs/` convention (raw = unstructured dumps, wiki = agent-authored structured "Wikipedia-style" articles, outputs = deliverables like slide decks) is presented as one option, not a requirement — "you don't have to do raw, you don't have to do outputs... you just need a map for the agent that makes sense." The load-bearing element he stresses is an `index.md` at every folder level so the agent always has a cheap, token-efficient way to find its way around a large vault, plus an agent-instructions file documenting vault conventions and a navigation pattern (shown on screen, open in an editor).
3. **[23:24-28:23] Level 3 — Interface/UI.** A custom web-app command center (on-screen labeled "V.A.U.L.T.": a particle-sphere visualization, token-burn/view-count metrics, one-click buttons like "Inbox Brief" that trigger a skill) and a parallel vault-app-plugin version ("command center" inside the vault app itself). Confirms explicitly that every button click is a **headless call to the coding agent CLI via its non-interactive invocation flag** — the terminal doesn't visibly open, but it's functionally identical to typing the command yourself. Notes a real, dated controversy: the CLI's maker briefly said headless usage would bill against the $200 API-credit tier instead of the flat-rate subscription plan, then walked it back (as of this video, headless invocations still pull from the subscription plan).
4. **[28:23-31:20] Level 4 — Distribution.** Framed as "raising the floor" — handing the whole skill+automation+UI bundle to non-technical teammates or clients who will never open a terminal. Web-app version is easy to distribute (GitHub repo, zip file); the vault-app version needs more hands-on setup per recipient.

## How it works technically

The mechanism underneath every "level" in this video is ordinary, already-documented functionality of the coding agent CLI, stacked and named rather than invented:

1. **Skills** (a real, first-party feature of the coding agent CLI, built by its own vendor) as the unit of codification — packaged instructions/tools an agent loads for a specific repeatable output.
2. **Session-history mining** — the agent has access to its own prior session tool-calls, so it can be asked to scan the last N sessions and propose skills from what you actually did (not a special API, just a prompted read of local session logs).
3. **The desktop app's "routines"** — the existing scheduling/automation feature (name + instructions + cron-like schedule) used to promote a skill into a standing automation.
4. **A structured Markdown vault (a dedicated vault app or any folder tree) as memory** — no database, no vector store required in the base case; `index.md` files at each folder level are the actual technical trick, functioning as a cheap navigation map so the agent's search doesn't have to brute-force a large, unstructured tree (which the video ties directly to token cost and latency, not just tidiness).
5. **Headless invocation of the coding agent CLI** as the invocation layer for every UI button, voice command, or distributed tool — this is the single mechanism that makes Levels 3 and 4 possible; there is no separate agent runtime.
6. **A custom web app or vault-app plugin as presentation only** — built the same way any agent-generated web app or vault-app plugin is built (describe the desired UI, wire it to the vault and the skill set, let the agent scaffold it); the video is explicit that this layer contributes none of the underlying "power," only visibility and shareability.
